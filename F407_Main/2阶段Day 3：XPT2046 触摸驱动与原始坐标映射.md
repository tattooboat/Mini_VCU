# Day 3：XPT2046 触摸驱动与原始坐标映射

## 1. 本日目标

- 完成 XPT2046 GPIO 模拟 SPI 通信。
- 能够读取触摸原始 X/Y 数据。
- 能够识别触摸按下和松开。
- 将原始坐标映射到 ILI9341 的 320×240 像素坐标。
- 为后续 LVGL 输入设备驱动做好准备。

## 2. 硬件与引脚

主控：STM32F407VGT6  
LCD：2.4 英寸 ILI9341，分辨率 320×240  
触摸控制器：XPT2046

| XPT2046 引脚 | STM32F407VGT6 引脚 | 用途 |
|---|---|---|
| T_CLK | PB5 | 模拟 SPI 时钟 |
| T_CS | PB15 | 触摸芯片片选 |
| T_DIN | PB4 | 主控发送数据 |
| T_DO | PB3 | 触摸芯片返回数据 |
| T_IRQ | 暂不连接 | 当前使用轮询方式 |
| VCC | 按模块规格接电源，确认是否支持 3.3V | 供电 |
| GND | GND | 共地 |

注意：T_DIN 和 T_DO 方向不同，不能接反。PB3/PB4/PB5 可能与调试功能复用，因此 CubeMX 的 SYS Debug 应保留 Serial Wire（SWD），并确认这些 GPIO 配置与工程一致。

## 3. 已完成的驱动功能

驱动文件：`Int_XPT2046.c`、`Int_XPT2046.h`

核心接口：

```c
void Int_XPT2046_Init(void);
uint8_t Int_XPT2046_ReadRaw(uint16_t *x, uint16_t *y);
uint8_t Int_XPT2046_IsPressed(void);
```

当前读取命令：
- `0xD0`：读取 X 通道
- `0x90`：读取 Y 通道
- `0xB0`：读取 Z1
- `0xC0`：读取 Z2

当前 `Int_XPT2046_IsPressed()` 使用 Z1/Z2 的初步阈值判断。实测按下与松开结果正确。若更换模块或出现误判，应重新采样 Z1/Z2，并调整判断策略。

## 4. FreeRTOS 中的调用位置

由于 `osKernelStart()` 启动调度器后，`main()` 后面的普通 `while (1)` 通常不会继续执行，因此触摸读取应放在实际运行的 FreeRTOS 任务中。

在已有测试任务中轮询触摸，避免创建重复任务或阻塞其他应用：

```c
if (Int_XPT2046_IsPressed())
{
    Int_XPT2046_ReadRaw(&g_touch_raw_x, &g_touch_raw_y);
}
osDelay(20);
```

如果坐标变量定义为 `volatile uint16_t`，建议在头文件中统一声明：

```c
extern volatile uint16_t g_touch_raw_x;
extern volatile uint16_t g_touch_raw_y;
```

更规范的做法是让驱动接口也接受 `volatile uint16_t *`，避免强制类型转换。

## 5. 原始坐标实测记录

用户实测数据如下（十六进制）：

| 位置 | raw X | raw Y |
|---|---:|---:|
| 不触摸 | `0x0000` | `0x0FFF` |
| 左上角 | `0x0DD9` | `0x0DDF` |
| 右上角 | `0x0D9E` | `0x0213` |
| 左下角 | `0x02D7` | `0x0E38` |
| 右下角 | `0x0290` | `0x02B7` |
| 中央 | `0x0812` | `0x0872` |

初步结论：
- raw X 主要反映屏幕上下方向：上侧数值较大，下侧较小。
- raw Y 主要反映屏幕左右方向：左侧数值较大，右侧较小。
- 当前方向需要交换两个轴，并反转方向。
- 不触摸时的读数不能当作有效坐标；先判断触摸状态，再更新有效坐标。

## 6. 初始坐标映射

初始近似映射参数：

```c
#define LCD_WIDTH       320
#define LCD_HEIGHT      240

#define RAW_X_TOP       3500
#define RAW_X_BOTTOM     650
#define RAW_Y_LEFT      3600
#define RAW_Y_RIGHT      600
```

映射思路：

```c
screen_x = (RAW_Y_LEFT - raw_y) * 319
            / (RAW_Y_LEFT - RAW_Y_RIGHT);

screen_y = (RAW_X_TOP - raw_x) * 239
            / (RAW_X_TOP - RAW_X_BOTTOM);
```

结果需要限制在 `screen_x = 0..319`、`screen_y = 0..239`。以上参数只是初始近似值，后续应按四角及中心的实测结果校准。

## 9. 重要注意事项

- 当前工程没有 `lv_version.h`。可能是 LVGL 源码尚未加入、头文件目录未加入 Keil，或所用库布局不同；不能仅凭这一点断定版本。
- 不要混用 LVGL 8 和 LVGL 9 的显示/输入 API。
- LVGL 的定时处理函数应由单一任务或单一执行上下文定期调用，避免多个任务同时调用。
- 保留目前能正常工作的 LCD、CAN、电机和 FreeRTOS 代码；每次只增加一个可验证的功能。
